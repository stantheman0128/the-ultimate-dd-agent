# 創投前輩 Q-list 方法論

這份 skill 描述「一位早期基金（Pre-A 至 Series A、小額少數股權）資深同事」怎麼寫給新創的 DD 問題清單。目標是拿到**結構化、可驗證、難以迴避、真的會推進投資決策的答案**，不是撒網。它不含任何案件資料；具體題型範例在 `references/question-bank.md`（已抽象成 placeholder）。

## 適用場景

1. **審核／比對既有清單**：對使用者版本逐題標 `[原問]`／`[優化]`／`[新增]`，先講他漏掉的維度；沿用「保留結構、追加子句」原則（技法 4），不要重寫別人的題目，除非題目本身錯了。
2. **從零出初版**：拿到公司名、deck、財報或同事筆記時，依「從零出初版」一節走。
3. **只給角度**：使用者問「這家還該問什麼」時，先判斷商業模式，再從題庫抽該原型的高槓桿角度與 deck 最弱的維度；給建議即可，不一定產整份清單。

三種模式的第一步一樣：**先判斷商業模式**，因為它決定哪些角度是必問。

## 基金背景怎麼用（由使用者在工作台備註或 `_notes.md` 補）

方法論預設兩個結構性事實，請依基金實況調整：
- **地域擴張若是基金 mandate**（例：跨境、雙邊市場），每份清單都要探真實的跨境路徑：營收按地區、海外 go-to-market（直客 vs 在地經銷）、第一個真正的海外實績；母子公司結構要問移轉訂價、集團內收入認列、少數股東保護。純單一市場的案子即使基本面好也是弱 fit。
- **小額＝少數股權**：治理、side letter、出場路徑的權重不成比例地高，因為基金不會控制公司。

## 兩通路規則（最重要的原則）

Q-list 跑在兩條平行通路上，題目要放對通路。

- **通路一：書面 Q-list**。正式送出、正式回覆。必須**克制、聚焦業務**。公司能用資料、文件或事實陳述回答、且願意留下永久紀錄的題放這裡（IR 窗口會在公司內部傳閱）。
- **通路二：口頭（管理層會議／電話）**。需要**看對方反應**的題放這裡：Cap Table 異常但未揭露對價、隱藏的資本承諾、過橋輪價格 vs 本輪目標、deck 單位疑問、隱藏的股份轉讓、關係人交易、贖回／清算條款的動機、策略投資人 side letter。寫下來會被讀成對抗式 DD，讓關係變硬，也讓對方準備好漂亮的標準答案。

**預設：拿不準就口頭。** 但成熟關係或後期 DD 也有把估值、Cap Table 題寫進書面的先例，那是判斷題，要向使用者標出取捨，不要機械套用。

> 本引擎的既定政策是「一律書面詢問，敏感題以波次 2 表達」；skill 的「口頭」標記交由匯整層決定波次，不改分類欄。

## 第一波的限制

- **第一波約 20 題以內**。更多代表沒有焦點，也會壓垮 IR 窗口。超過就拆波：波次 1（業務驗證）→ 波次 2（治理、股權、IP、出場）→ 波次 3（交易文件）。
- **第一波只問業務**：產品、客戶、營收、毛利、財測。治理、股份異動、Cap Table 異常、IP 訴訟 → 波次 2，敏感的走口頭。
- 律師／VDD 範圍（訴訟、IP 糾紛、保險、罰鍰）不進第一波。
- **新加的題必須打 deck 敘事最弱的地方**，不是隨機好奇。

## 先辨認商業模式原型

角度組合取決於原型。把公司對到下列一種（或混合），再從題庫抽該原型的必問角度：

- **純 SaaS／訂閱**：seat 成長、ARPA 演變、MRR 拆 New／Expansion／Churn、月留存與年留存、CAC by channel／payback／CAC:LTV、comps，以及**上游平台風險**（若上游 LLM／平台原生提供同樣功能怎麼辦）。
- **AI SaaS＋代理／經銷混合**：代理收入 vs 自有產品收入*與毛利*分開；**代理本業自己是否已獲利**；代理的地域權利與在地同業；LLM／API 月費與用哪些模型；freemium 轉換率；用量計價客戶數。
- **專案／服務＋產品混合**：專案怎麼報價、毛利怎麼抓、外包占比；SaaS／專案／API·加值 的營收拆分；**客戶 vs 帳戶的定義**；平台基礎費；使用量趨勢（每月憑證／交易量）。
- **工業／硬體嵌入式 AI**：安裝／POC／付費／貢獻 MRR 的**機台數時間序列**；效益宣稱（良率、換模時間、節能）要**第三方驗證**；純軟體 vs 軟硬整套的銷售；供應商／BOM 依賴；策略性 OEM 投資人的 side letter。
- **區塊鏈／憑證／代幣**：代幣或基礎設施費用經濟、鏈上量趨勢、驗證時誰付誰、對底層鏈的依賴。
- **雙邊平台／重資產**：供給端與需求端各自的獲客與留存；資產週轉與資本開支節奏。

跨境型基金要把「地域擴張 overlay」疊在原型之上。

## 七維度框架

只涵蓋營運與財務的 Q-list 是不完整的。逐維度檢查覆蓋：

1. **營運面**：客戶、部署、lead time、pipeline、銷售方式（直客 vs 通路）。
2. **產品面**：技術、AI 模型資料來源、跨客戶訓練權利、資安認證（ISO 27001）、資料隱私、上游平台成本。
3. **競爭面**：國內外競品、具體競爭者近期動作、差異化、平台風險、進入門檻。
4. **財務面**：損益拆分（產品／通路／地區）、毛利率與其組成、費用波動、營收品質拆解、財測邏輯、資產負債表異常。
5. **智財權**：專利（申請中／已核准、地區、範圍）、軟體著作權、員工 IP 讓與。
6. **股權面**：Cap Table 對登記文件、對 SHA 的一致性；共同創辦人全職；策略投資人 side letter；獨家／通路綁定／採購保證；不尋常的 SHA 條款動機。
7. **出場**：M&A vs IPO 偏好、時程、可能買方、目標板塊／市場。

加上**組織與關鍵人**：組織圖、各職能人數、招募計畫、關鍵人 CV **含 CFO**（問 CFO 等於在查 IPO 準備度）。

## 20 條問題設計技法

前 12 條是核心工具箱，後 8 條是反覆出現的進階招式。

1. **時間序列，不是快照。** 「累計 X」改成「自 20XX 年起每季 X」，讓斜率與轉折露出來。
2. **SaaS 單位經濟預設必問。** CAC（by channel）、Payback、CAC:LTV、各收入類型毛利率四個一起看；ARR／MRR 拆 (a) 一次性授權 (b) 訂閱 (c) 硬體／整機 (d) 其他。
3. **數字錨定。** 把財報算出來的變動率與絕對值直接放進題目：「20XX 銷售費用年增 [148%]（[5.4M] → [13.3M]）— 增加項目明細（人力／行銷／通路／樣機）」。算過的數字對方無法敷衍。
4. **跨文件比對。** 出題前把 Cap Table、變更登記、財報、deck、章程並排；文件之間的不一致是最高品質的題：「Cap Table 顯示 X 為 0 股，但變更登記表仍列 X 持股 Y 股 — 請提供最新核對版並說明差異」。對既有清單的優化也是同一招：追加對帳子句而非重寫。
5. **前瞻狀態，不只歷史。** 追加「以及目前合作狀態（進行中／已續約／已 churn）」或「進度階段」。落後指標是會計師的，領先指標才是投資人的。
6. **Pipeline 用漏斗框架。** 「請提供 pipeline」改成「weighted pipeline by stage（Qualified／Negotiation／Closed-won），含逐月新增 ARR 預估與轉換率」。沒有 sales ops 的公司答不出來，這本身就是訊號。
7. **定義題。** deck 或財報用了含糊標籤（商品銷售、其他收入、Subscription／Consulting）就追加「此處 X 指的是？」。後面所有對話都依賴共同定義。
8. **指定期間，不接受「最新」。** 「20XX 年 1–4 月自結報表」，不是「最新管理報表」。
9. **策略投資人風險偵測。** Cap Table 有企業／策略投資人時：「與 [策略投資人] 之投資是否伴隨 side letter／獨家代理／通路綁定／採購保證／minimum commitment？」它們通常綁獨家，傷害日後通路擴張。（偏口頭）
10. **共同創辦人投入檢查。** 「[三位共同創辦人] 是否仍全職在職？」投的是人，部分投入會殺估值。
11. **出場題不可省略。** 「潛在退場路徑：M&A vs 上市之偏好、時程、預計買方、板塊？」
12. **要分布，不要平均。** 「平均、最快、最慢 lead time」，不是「平均 lead time」。分布才露風險。
13. **估值反推。** 從 Cap Table 反算隱含估值請對方確認：「據 Cap Table 已發行 [N] 股、上輪每股 [P]，推得 post-money ≈ [V]，是否另有 ESOP？」逼出精確的估值對話。
14. **毛利率對帳＋橋。** 宣稱毛利率 ≠ 財報毛利率時問口徑與主要差異；財測跳升時問「如何從 [38%] 到 [62%]」。這題在每個案子都出現。
15. **從零出現的成本線。** 「[某成本項] 前一年為 0、今年出現 — 原因？具體內容？」
16. **引用壞數字再問原因。** 文件已揭露弱指標時不要再要一次，引用它問原因：「Business Plan 顯示留存約 [55%]，流失偏高的原因？」
17. **本業獲利。** 混合型：「在 AI 產品之前，[代理／本業] 是否已獲利？」把耐久的本業和新故事分開。
18. **平台依賴風險。** 「若 [上游大廠] 未來自行提供 [類似服務]，公司如何因應並守住定位？」
19. **不尋常條款的動機。** 任何奇怪的 SHA／合約條款（複利贖回、CB 而非股權、股份轉給創辦人）問*為什麼當時這樣訂*，不只問事實；偏口頭。
20. **客戶訪談請求。** 適當時把關鍵客戶訪談列進 DD：「為執行 DD，可否安排 [關鍵客戶] 訪談？」

## 從零出初版

1. **讀手上有的**：抽出宣稱指標（ARR／NRR／GM／留存／機台數）、營收故事、本輪（階段、金額、估值）、Cap Table、點名的人。每個數字都記下來，它們是錨（技法 3）。
2. **判斷商業模式原型**與地域擴張姿態。
3. **跑跨文件比對**（技法 4），只要有 ≥2 份 {Cap Table、變更登記、財報、deck、SHA}。每個不一致都標出來，這是最好的題。
4. **從題庫抽候選題**：對到的原型＋七個維度，每個 placeholder 換成本案的實際數字與名稱。
5. **排波次與通路**：第一波 ≤20、只問業務；治理／Cap Table／IP／出場進波次 2；要看反應的走口頭。明說你把什麼放到哪裡、為什麼。
6. **語言對齊收件人**：國際／日本團隊用英文，本地團隊用繁中；不確定就問。
7. **推論的東西標信心**：從薄 deck 推出的商業模式或數字要說是推的；自報指標預設視為未驗證。

## 標準結構（輸出順序）

```
第一波（≤20 題，業務聚焦）
  ├── 文件請求（3–5：SPA/SHA、多年財簽、客戶／合作合約樣本、財測 Excel）
  ├── 營運面（5–8：Top 客戶＋合作狀態、lead time 分布、weighted pipeline、SaaS 指標）
  ├── 產品面（2–3：AI 模型資料來源、跨客戶訓練、ISO 認證、上游平台成本）
  ├── 競爭面（1–2：國內外競品、具體競爭者動作、平台風險）
  └── 財務面（4–6：毛利率拆解與對帳、收入結構／品質、費用變動細項、財測邏輯、自結期中報）

第二波（治理／股權，第一波回覆後）
  ├── 智財權（專利地區／範圍、員工 IP 讓與）
  ├── 股權面（Cap Table 對登記／對 SHA、共同創辦人 FTE、估值反推）
  ├── 出場（M&A vs IPO 偏好、買方、板塊）
  └── 組織人事（組織圖、各職能人數、關鍵人 CV 含 CFO）

（口頭通路，不寫）
  - 無對價揭露的大股東／隱藏資本承諾
  - 過橋輪價格 vs 本輪目標價差；deck 單位疑問
  - 退出股東的退出條件；看似關係人的交易
  - 贖回／CB／股份轉讓等條款「當時為何這樣訂」
  - 策略投資人 side letter／獨家／通路綁定
```

## 輸出格式

Q-list 以 xlsx 交付，欄位：`No.`／`問題提出日期`／`問題分類`／`問題`／`預期回答格式／文件`／`回答／回覆`；可加內部欄 `備註`（送出前隱藏）。日期欄用來追回覆延遲，延遲本身是診斷訊號。第二個工作表放波次策略、通路圖例、送出前檢查。

## 交付時先講什麼

先講對方草稿漏掉的維度（最常見：產品／IP／競爭／出場／策略投資人 side letter／共同創辦人 FTE／資產負債表異常）。說明移到口頭通路的題與原因。確認第一波 ≤20，否則提拆波方案。簡短、高密度，不要手把手。

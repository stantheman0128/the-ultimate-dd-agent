# 專案對話：漸進式文件讀取

## 原本如何處理

`index_doc.py` 已負責把 PDF/PPTX 抽成逐頁文字、Excel 抽成儲存格值與公式。問題在原本問答把大量索引內容組合成單次 context；有索引不等於有檢索。新版本把文件解析、可搜尋索引、模型讀取分開。

## 已實作的資料路徑

1. 上傳／重建：沿用解析器，保留頁碼、工作表、儲存格、公式及抽取警告。Excel 改為 read-only 串流走訪，產生輕量 metadata sidecar。
2. 本地預處理：`retrieval.py` 用 SQLite FTS5 建文件導覽與片段。文字每片最多 2,400 字、重疊 200 字；Excel 按 35 個非空格分批並帶表頭，再分片。文件描述是機械摘錄，不宣稱完整語意摘要。
3. 增量更新：依索引及原件 metadata 檢查變更，僅重建變更文件；刪除／封存文件退出檢索。原件比索引新時排除舊片段並提示重建。引用 ID 含版本簽章，舊引用不會誤指新文字。
4. 每輪對話：只先提供一頁文件導覽（最多 12 份）、有限近期歷史及問題。模型用 `search_documents` 找片段，`read_chunk` 讀必要原文；需要更多導覽用 `list_documents`，舊對話用 `search_history`。不把所有文件的摘要一次塞入模型。
5. 回答：SSE 串流顯示查找過程、讀過的來源及實際累計 token。引用可打開原文件；已更動／移除來源可讀本輪保存的文字快照。快照功能上線前的舊引用不會自動補造。

搜尋使用 BM25、英文詞與中文 bigram，可由模型改寫中英查詢。既有字卡、facts、草稿與備註可搜尋，但標為分析產物，不視為已驗證原件。文件內容視為資料，不作為系統指令。

## 預算與容量

- 每次模型請求：序列化 system、工具 schema、history、問題及工具結果合計不超過 48,000 UTF-8 bytes，另預留 transport 空間。這是 byte 上限，不是精確 12,000 tokens 承諾。
- 每輪最多 6 次工具呼叫、7 次模型請求，每次最多輸出 2,200 tokens；累計費用取決於實際模型請求數。UI 顯示的是本輪所有模型呼叫的累計 token。
- 單次工具結果最多 6,500 bytes，搜尋最多 8 個預覽；過長結果裁切並標記。必要時移出較早工具內容，避免 context 隨 corpus 增長。
- 模型近期歷史最多 8 則，內容約 6,000 bytes；完整對話留本機，較早資訊按需搜尋。
- SQLite 索引在磁碟；Node 文件快取最多 8 份／32 MB。首次建立仍需逐份解析原索引 JSON，單一巨型文件的解析記憶體與總索引耗時尚未壓測。

## 對話介面與儲存

「專案對話」是預設第一分頁，包含案件內對話清單、串流訊息、追問、停止、重問、複製及來源抽屜。Enter 送出、Shift+Enter 換行。搜尋分頁保留純全文搜尋。

紀錄寫入 `<案件>/_analysis/conversations/`，檢索庫在 `_analysis/retrieval/`，均 Git 忽略；瀏覽器只存選中的對話 ID。同案同對話禁止並行生成；錯誤、中斷、取消不標為成功。重開頁面可載入已保存對話。專案對話是唯讀，執行 DD 流程仍使用原工作台按鈕。

優先使用 OpenAI API key（Responses `store:false`）；未設定 key 時，`codex-chat-client.js` 透過既有 Codex CLI 登入回傳結構化工具請求，沿用同一個本案檢索、歷史、工具上限與取消流程。CLI 在暫存工作目錄以唯讀模式執行，停用原生檔案／Shell、插件及外部工具；由工作台執行允許的文件查詢。48,000 bytes 是應用層輸入上限，不包含 CLI 自身提示；API 的 2,200 output tokens 參數不適用 CLI。CLI 模式不啟動需要 API key 的背景記憶整理。模型仍透過網路處理本轮片段，資料並非完全不離開本機。

## 驗證與已知限制

自動測試涵蓋 1,000 頁合成文件、中文查詢、指定頁碼、70 份文件中的範圍搜尋、Excel 公式／儲存格、過期來源、跨案隔離、長對話、6 次工具讀取上限、失敗、取消與同對話競爭。

真實 API 演練：同一份年報 p.486 問題，舊版輸入 411,754 tokens；新版工具迴圈累計 22,569 tokens（約少 94.5%），只讀一個證據片段。接續 US$4M 募資問題累計 23,737 input tokens，正確區分募資門檻與控制權變更。此為單案實測，不代表所有問題的固定節省比例。

限制：FTS 是詞彙搜尋，跨語言同義詞可能漏搜；尚未引入 embeddings/reranker。掃描文件依既有 OCR 能力，沒有成功抽取的頁面不能視為已覆蓋。既有 Excel 抽取仍有每工作表 40,000 個非空格上限，會標記不完整；無法承諾讀完整個超大試算表。跨輪同名檔的舊索引格式會提示碰撞，需改名或後續遷移索引鍵。全案風險盤點仍應跑完整 DD pipeline，片段問答不等同完整盡調。

後續擴充應以資料量及檢索評測驅動：先遷移原件串流入庫與 Excel 無截斷分批索引、建立跨語言／表格命中率測試，再評估混合向量檢索與語意文件摘要；不要為所有文件預付昂貴的 LLM 摘要成本。

## 採用依據

重用現有解析器與 OpenAI SDK，以 Python 標準庫 SQLite FTS5 補上檢索，不增加常駐向量資料庫或新套件。SQLite 為 public domain；此方案沒有額外索引服務費，模型 API 按實際用量計費。

- [SQLite FTS5：全文搜尋、BM25](https://www.sqlite.org/fts5.html)
- [OpenAI Function calling：由應用執行受限工具](https://developers.openai.com/api/docs/guides/function-calling)

## 多格式與中文索引（2026-09-12 更新）

以下更新取代前文「僅機械導覽」：每份文件現在另有 AI 繁體中文用途說明、中英關鍵字、取樣位置、模型／用量及覆蓋聲明；導覽最多取 32 個均勻分布位置（含末頁），約 18,000 字元，並非全文件語意摘要。全文片段仍独立檢索。圖片描述與文件摘要以 `metadata` 標示，只供找文件，不冒充原件。

| 格式 | 抽取與結構 |
|---|---|
| PDF | 原生逐頁文字、文字區塊座標；少字或含圖片頁以 OCR＋視覺辨識補讀，保留原生文字 |
| XLSX／XLSM | 工作表、儲存格、值與公式；不執行巨集或重算公式；現存 40,000 格上限仍明確標記 |
| CSV／TSV | UTF-8／Big5／UTF-16，保留列欄與儲存格地址；不將文字公式當程式執行 |
| PNG／JPEG／WebP／TIFF／BMP／GIF | 校正 EXIF 方向、多影格逐張處理；OCR 文字、表格轉錄、中文視覺描述分開記錄 |
| PPTX／DOCX | 文字／表格及內嵌圖片辨識；DOCX 段落不假冒實體頁碼；不保證 SmartArt、Excel 圖表、特殊嵌入物件皆被抽出 |
| TXT／Markdown | 文字分段、中文用途摘要 |
| 其他／損毀／加密 | 顯示抽取失敗及原因，請轉成上述格式；不是已完成索引 |

OCR 使用既有 PyMuPDF 與 Tesseract 語言資料；視覺與中文摘要重用 OpenAI Responses SDK，圖片先縮至最長邊 2400px。沒有 API key 或 API 失敗時保留本地抽取結果並標為部分完成。預處理會將抽樣文字／需要辨識的圖片傳到已設定的 OpenAI API，按用量計費；DELTA 起預設停用額外模型描述，只有 `QLIST_INDEX_AI=1` 才啟用，`QLIST_INDEX_MODEL` 可指定模型。原件未變更時不重做；要重試 AI 摘要請按重建索引。影像頁甚多時，首次視覺處理可能較久；同一案件的索引工作依序執行。

全文搜尋和專案對話共用 SQLite 檢索；繁簡中文詞彙可展開為常見英語財務詞，也能命中文件的中文 AI 描述。這不是任意跨語言同義詞均命中的保證。文件清單可展開中文說明，狀態與警告可查；搜尋結果區分原文與 AI 描述，並可檢視／下載來源。

本機繁中／英文 OCR 資料已裝在 `_workbench/.tessdata/`（Git 忽略）。其他機器可執行 `python3 _workbench/setup_ocr.py` 安裝；使用 Tesseract 官方 Apache-2.0 語言資料，不需另起 OCR 服務。

新增驗收：6 種圖片格式與掃描 PDF 的 OCR、Big5 CSV、Excel 公式、中文搜尋英文 PDF、AI 摘要／原文分離、降級狀態、千頁摘要取樣預算。合成發票 PNG 真實模型辨識得到 USD 18,600 與 2026-10-15，中文「倉庫巡檢攝影機」可找到該圖片；英文質押 PDF 以中文「設備質押」可命中原文。驗收資料留在本機 `多格式驗收_合成資料/`，不含客戶資料。

來源：[PyMuPDF OCR](https://pymupdf.readthedocs.io/en/latest/recipes-ocr.html)、[Tesseract 官方語言模型](https://github.com/tesseract-ocr/tessdata_fast)、[OpenAI 視覺輸入](https://developers.openai.com/api/docs/guides/images-vision)。

DELTA 索引契約與設定以 [README.md](README.md#delta全文視覺頁與陳述核對) 為準：掃描頁保留本地 OCR，原生索引不呼叫模型；獨立圖片不預先抽文字，改標視覺頁供 extractor 讀 PNG。

# 對話記憶：實作與操作

對話輸入區的「使用記憶」開啟範圍選擇與管理。團隊通則與本案固定可用，最多另選 20 案；所選專案記錄於 conversation.memoryProjects，新對話預設清空跨案選擇。僅開放記憶，不開放其他案件原始文件。

## 保存與索引

`_private_memory/` 位於 repo 根目錄但由 Git 忽略；不更動公開 AGENTS.md 或 question-bank.md。

- `general/MEMORY.md`：通則目錄與固定核心；`entries/<uuid>.md` 保存 JSON fenced block，包含內文、來源、確認狀態與最多 20 筆修訂。
- `projects/<案名 UTF-8 hex>/`：本案記憶，同樣以 Markdown 為正式內容。
- `memory.sqlite3`：可重建的 SQLite FTS5 索引；英文詞與中文雙字分詞。每次內容變動移除舊索引，下次查詢增量建立所選範圍。沒有額外向量服務費。
- `summaries/<conversation-id>.json`：增量工作摘要；與記憶範圍版本、手動修改 generation 綁定。
- `jobs/<message-id>.json`：可恢復背景整理工作與獨立模型用量。完成回答後排入；啟動時恢復 pending/running，失敗可由 UI 重試。修改記憶後過期工作不重放。

檔案以原子 rename 寫入，檔案 mode 0600、新增目錄 mode 0700。Markdown 內容可供查看；建議透過 UI 編輯以保留修訂及清理索引。原始對話檔案繼續獨立保存。

## 回答讀取

每次提供固定核心、最近四筆使用中的通則摘要、依問題搜尋的相關記憶（合併最多八筆，各 300 字），以及至多 1,000 字對話摘要。完整記憶透過 search_memories/read_memory 讀取。所有記憶仍計入既有每次 48,000 UTF-8 bytes 模型輸入限制與最多六次工具呼叫，不宣稱此 bytes 限制等於固定 token 數。

只有 active 條目可以進模型。read_memory 後端重新檢查所選範圍與狀態；跨案 ID 無法繞過限制。文件檢索維持本案。團隊通則的模型輸出隱去來源案件名稱與原文件名；原始追溯僅在管理介面呈現。回答另外呈現參考記憶標題和版號，不把它當成原件引用。

變更跨案選擇後，舊範圍的對話訊息不再注入模型或歷史搜尋，但仍可在畫面閱讀。手動修改/刪除記憶使舊摘要與回答背景失效。刪除會清除內文和修訂、移除派生索引，保留無內文 tombstone 防止重放；原始對話不會因此被刪除。

## 背景整理與通則學習

每個成功回答新增一個工作，另呼叫同一設定模型，輸入受限的最新問答、近期相關條目與工作摘要；最多三筆專案觀察、一筆通則候選。工作有獨立用量，增加一次模型請求。未完成/取消的回答不整理；舊對話不會在升級時自動批次回填。

專案自動觀察可供檢索，但標「待查證」；使用者逐字明確交代的記憶標「使用者確認」。通則預設 candidate，人工確認後才 active；明確要求所有專案以後採用的使用者原句，可直接啟用。提問、否定與假設句採保守處理，不直接算確認。分類仍是模型判斷，使用者可修正。

整理器可提出 supersedes。若有使用者明確更正，舊條目停用並留版本；非明確更正則新條目待確認，使用者批准後再取代。沒有可靠比對到的衝突不會自動合併，應透過管理介面校正。引用其他專案記憶的回答不交給本案整理器作為事實輸入，避免跨案內容被間接轉存成本案事實。

## 驗證範圍

自動測試涵蓋中文檢索、跨案隔離、候選排除、上下文大小、撤回範圍、修訂競爭、刪除與索引移除、背景失敗重試與重啟去重、整理中手動修改、舊記憶被取代及全域來源遮蔽。

目前為單一使用者本機服務，尚非多人帳號/團隊權限模型；搜尋採 FTS，尚未加入語意向量或同義詞擴展。不會微調模型權重，也不直接將記憶發布為公開題庫。大量記憶下的索引與品質仍須持續評估。

實際驗收：隔離合成案上完成真實模型問答與背景整理；將訪談週三改為週四後舊條目停用，另開全新對話成功回憶週四安排。已檢查專案選擇重載保留、UI 刪除與 390px 手機面板無橫向溢出。驗收資料未寫入正式案件。

## 結案蒸餾與團隊通則

`knowledge/question-bank.md` 是蒸餾來源；成功結案／本輪蒸餾，以及開啟記憶 API 或開始對話時同步。依題型表格列、清單與段落建立最長 1800 字的通則條目，保留来源檔案、行號、原文與內容指紋。每輪提供 12 條標題導覽及有上限的相關摘錄，以 list_team_memories、search_memories 和 read_memory 補讀，不載入整份 MD。

有效版本保存於 Git 忽略的 `_private_memory/general/entries/*.md`。人工修訂是私有覆寫，不改寫公開題庫，也不回灌到批次 DD 引擎。後續蒸餾改動同一條目時，保留人工版本並標示衝突；來源移除時停用自動條目，人工版本保留並提示。來源以章節／題名／同名序號識別；題型重命名視為新條目，需人工整併既有修訂。

對話的 propose_memory_update 只產生草稿；完成回答顯示「檢視並套用」。使用者比較並保存後才生效，採 revision 樂觀鎖避免過期草稿覆蓋新版。有草稿的回合不觸發背景學習，避免未套用就寫入。

蒸餾原文、修訂歷史與衝突提示可在記憶庫查看；案件蒸餾報告與原始文件不因此開放跨案讀取。記憶是背景，不是本案原件證據。設計參考：https://docs.langchain.com/oss/javascript/langchain/long-term-memory 。

測試涵蓋重啟冪等、中文搜尋、分頁及長度上限、人工覆寫、來源變更衝突、刪除不復活、來源移除失效，以及修訂草稿持久化與過期版本拒絕。

本機驗收：既有題庫同步為 36 條記憶；真實模型成功查詢毛利查核通則並引用記憶，第二輪成功產生通則修訂草稿，瀏覽器可開啟草稿、查看修改前文字及來源；390px 視窗無橫向溢出。驗證草稿未套用。38 項 Node 測試通過；模型驗收與確定性測試分開記錄。
